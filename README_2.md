# marketplace-agent — синхронизация карточек Ozon / WB / Avito / Яндекс Маркет

Первый этап: подключиться к Ozon и Wildberries через официальные API и
посмотреть на реальные данные из ваших кабинетов. Дальше на основе этого
построим общий каталог и синхронизацию цен/остатков/заказов.

Почему через GitHub Actions, а не напрямую с компьютера — по той же причине,
что и в проекте realty-agent: сеть, из которой я работаю, не пропускает
запросы к api-seller.ozon.ru и content-api.wildberries.ru напрямую, а у
GitHub Actions доступ в интернет обычный, без ограничений.

## Настройка (если репозиторий новый)

1. Создайте приватный репозиторий на GitHub, загрузите туда все файлы этой папки
   (включая скрытую папку `.github` — на Mac показать скрытые файлы: `Cmd+Shift+.`).
2. Settings → Secrets and variables → Actions → New repository secret, добавьте:
   - `OZON_CLIENT_ID`, `OZON_API_KEY` — из кабинета Ozon (Настройки → API-ключи)
   - `WB_API_TOKEN` — из кабинета WB (Настройки → Доступ к API, Personal access token,
     категории: Контент, Цены и скидки, Маркетплейс)
3. Settings → Actions → General → Workflow permissions → выбрать
   "Read and write permissions" → Save.

## Как проверить, что ключи работают

Вкладка **Actions** → workflow **marketplace-agent** → **Run workflow** →
в списке команд выберите `test-ozon`, запустите. Затем то же самое с `test-wb`.
В логе запуска будет написано "соединение работает" или ошибка с описанием.

## Как посмотреть реальные данные из кабинетов

Так же через Run workflow, команды `fetch-ozon` и `fetch-wb` — они сохранят
списки товаров/карточек в файлы `data/ozon_products.json` и `data/wb_cards.json`
прямо в репозитории (workflow сам закоммитит их обратно). Откройте эти файлы
на GitHub, чтобы увидеть, что реально лежит в кабинетах — это нужно мне, чтобы
спроектировать общий каталог правильно, под ваши настоящие товары и категории.

## Про склад WB

Перед тем как настраивать остатки на WB, нужно узнать ID вашего склада —
команда `wb-warehouses` выведет список в лог запуска. Найдите там нужный
склад и впишите его ID в секрет `WB_WAREHOUSE_ID`.

## Полное редактирование карточек Ozon (название, описание, цена, фото)

Команды, по порядку:

1. **`build-ozon-catalog`** — собирает `data/ozon_catalog.xlsx` из уже
   выгруженного `data/ozon_products.json` (сначала должен быть выполнен
   `fetch-ozon`). Откройте файл на GitHub → Download, отредактируйте в Excel
   что нужно (название, описание, цену), сохраните.
2. **`attach-ozon-photos`** — если добавляете/меняете фото, см. раздел ниже.
   Не нужна, если фото не трогаете.
3. **`push-ozon-cards-dryrun`** — ПОКАЗЫВАЕТ, что будет отправлено в Ozon, но
   ничего реально не отправляет. Обязательно смотрите этот шаг перед
   push-ozon-cards, особенно в первый раз или после больших правок.
4. **`push-ozon-cards`** — реально отправляет правки в Ozon.

Чтобы загрузить изменённый xlsx обратно: на GitHub откройте папку `data`,
нажмите **Add file → Upload files**, перетащите ваш `ozon_catalog.xlsx` —
он заменит старый файл с тем же именем.

### Колонки в ozon_catalog.xlsx

- **Артикул (offer_id)** — не трогайте, это ключ, по которому находится товар.
- **Название**, **Описание**, **Цена**, **Цена до скидки** — редактируйте свободно.
- **Фото** — ссылки на картинки через `|` (первая ссылка = главное фото).
  Заполняется автоматически командой `attach-ozon-photos` (см. ниже), руками
  трогать не обязательно. Если оставить пустой — фото не меняются вообще.
  Если заполнить (руками или автоматически) — Ozon ПОЛНОСТЬЮ заменит фото на
  те, что в ячейке (нельзя добавить одну, не тронув остальные, — только весь
  список целиком).
- **Кол-во к продаже** — пока не используется этими командами (это отдельная
  будущая задача — общий остаток на все площадки), можно не заполнять.

### Как добавить/поменять фото — группами, по товару

1. В репозитории на GitHub создайте папку **`photos`** в корне (если её ещё
   нет): **Add file → Create new file**, в поле имени напишите
   `photos/.gitkeep` и нажмите Commit — так папка появится.
2. Попросите дизайнера выгрузить фото из Figma в JPG или PNG и назвать файлы
   по артикулу (offer_id) товара с номером через `_`:
   - `143210608_1.jpg`, `143210608_2.jpg`, `143210608_3.jpg` — 3 фото товара 143210608
   - `987654321_1.jpg`, `987654321_2.jpg` — 2 фото товара 987654321
   - если фото одно — можно просто `143210608.jpg`, без `_1`.
   Первое фото (`_1`) станет главным. Артикул смотрите в колонке "Артикул
   (offer_id)" таблицы ozon_catalog.xlsx.
3. Загрузите ВСЕ файлы разом в папку `photos` в репозитории:
   откройте папку `photos` → **Add file → Upload files** → перетащите все
   файлы сразу → Commit changes.
4. Run workflow → команда **attach-ozon-photos** → Run workflow. В логе
   запуска будет написано, для каких артикулов нашлись фото и сколько.
   Эта команда сама впишет правильные ссылки в колонку "Фото" в
   `data/ozon_catalog.xlsx` — руками ссылки собирать не нужно.
5. Дальше как обычно: `push-ozon-cards-dryrun`, проверить, `push-ozon-cards`.

Ссылка на фото в репозитории — прямая: если её открыть в браузере, увидите
саму картинку (а не страницу), так что при желании можно кликнуть и
проверить, то ли фото, прямо в логе запуска или в файле xlsx.

Важная оговорка: были сообщения о перебоях с доступом к файлам GitHub
(raw.githubusercontent.com) из России в 2026 году — стопроцентной гарантии,
что это будет работать стабильно, нет. Поэтому первую попытку стоит сделать
на ОДНОМ тестовом товаре и проверить, что фото реально появилось на Ozon,
прежде чем грузить фото на все товары.

### Можно загружать фото постепенно (сначала 1, потом больше)

Не обязательно сразу иметь 4-5 фото на товар. `attach-ozon-photos` заполняет
только те строки, для которых нашла файлы в `photos/` — остальные не
трогает (у них остаются текущие фото как есть). Можно сегодня загрузить
только `_1_главное.jpg` для части товаров, запустить push-ozon-cards — и
позже, когда появятся `_2`, `_3` и так далее, просто добавить файлы в ту же
папку и запустить `attach-ozon-photos` заново: она пересоберёт полный
список (старое + новое) для этого товара, ничего не потеряется.

### Авито — отдельная папка

У Авито свой формат/пропорции фото, и автоматизация по Авито в этом проекте
пока не построена (в планах). Чтобы не перепутать форматы, фото для Авито
стоит складывать в отдельную папку, например `photos_avito`, с тем же
правилом именования (`артикул_номер_описание.jpg`), не смешивая с `photos`.

### Безопасность

Методы Ozon, которые обновляют карточку, «перезаписывающие»: что не указано
в запросе — считается пустым и может стереться. Поэтому здесь трогаются
ТОЛЬКО поля, которые вы правите в xlsx (название/описание/цена/фото); всё
остальное (штрихкод, категория, размеры, вес, прочие характеристики)
копируется из уже выгруженных данных без изменений. Но всё равно: сначала
всегда `push-ozon-cards-dryrun`, проверьте вывод, и только потом
`push-ozon-cards`. Если что-то в выводе dry-run выглядит не так — не
запускайте push-ozon-cards, напишите мне.

## Полное редактирование карточек WB (название, описание, фото)

То же самое, что для Ozon, но для Wildberries — команды:

1. **`build-wb-catalog`** — собирает `data/wb_catalog.xlsx` из уже
   выгруженного `data/wb_cards.json` (сначала `fetch-wb`). Колонки:
   артикул WB (vendorCode), название, описание, фото, заметки.
2. **`attach-wb-photos`** — подставляет ссылки на фото из той же папки
   `photos/`, что и для Ozon (по имени файла — `артикул_номер_описание.jpg`).
   Если у вас общие артикулы на Ozon и WB — одни и те же файлы фото подойдут
   для обеих площадок, ничего дублировать не нужно.
3. **`push-wb-cards-dryrun`** — показывает, что будет отправлено, БЕЗ
   реальной отправки. Смотрите всегда перед push.
4. **`push-wb-cards`** — реально отправляет.

Особенности WB (важно, отличается от Ozon):

- **Название ограничено 60 символами** — если длиннее, WB его всё равно
  обрежет. В `wb_catalog.xlsx` такие ячейки подсвечены жёлтым.
- У WB название/описание и фото — это ДВА РАЗНЫХ метода обновления
  (у Ozon один). Значит, можно смело менять текст, ничего не подставляя в
  колонку "Фото" — фото при этом гарантированно не тронутся (это не как у
  Ozon, где нужно было заботиться о переносе старых фото).
- Пустая колонка "Фото" = фото этого товара не отправляются вообще (не
  подтираются и не трогаются).

## Сравнение Ozon и WB (без объединения)

Команда **`compare-ozon-wb`** — сравнивает уже выгруженные `data/ozon_products.json`
и `data/wb_cards.json` (сначала должны быть выполнены `fetch-ozon` и `fetch-wb`)
и строит `data/ozon_wb_compare.xlsx` с 4 группами строк:

- **Совпадает** — артикул продавца один в один на обеих площадках (регистр
  и пробелы не считаются). Это уже один и тот же товар, ничего делать не нужно.
- **Похоже, но не точно** (жёлтым) — артикулы отличаются символами
  (дефис, пробел и т.п.) — возможно, тот же товар, возможно, разные.
  Система НИЧЕГО не объединяет сама — надо посмотреть глазами и решить.
- **Только на Ozon** / **Только на WB** (оранжевым) — товар есть только на
  одной площадке, на другой карточки ещё нет.

Автоматическое объединение — только по точному совпадению артикула. Это
осознанное ограничение: неверное объединение двух разных товаров может
привести к ошибочному списанию остатка не с той карточки.

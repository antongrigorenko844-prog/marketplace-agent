# LEOPARTS — новый регламент цен и названий Авито (v2, 24.11.2026)

## Проблема предыдущего процесса

Раньше каждое согласование Excel требовало отдельного скрипта. На 95 изменений цен ушло
несколько запусков: опубликованный фид и базовый XLSX были согласованы, но
поздняя проверка Tilda обнаружила независимые site-only JSON цены, которые не
учитывались ранней проверкой. Отсюда лишние перезапуски. Цены обновлялись
последовательно с задержкой по 0,5 секунды. Названия попадали в фид, но
проверялись до завершения почасовой обработки Авито.

## Что реализовано

1. **Многоразовый конвейер** `scripts/avito_price_pipeline_v2.py` с одним
   одобренным manifest JSON для основной матрицы и старых ручных объявлений.
2. Два режима: `inspect` — строго чтение и план; `apply` — только
   точные цены и тексты, которые отдельно утвердил владелец. Никаких
   изменений при добавлении одного лишь кода.
3. Сверка по **Avito ID**, а не по редактируемому названию или догадке о SKU.
   Для основной карточки требуется соответствие конкретному SKU в последнем
   аудите и текущему фиду. Для старой карточки — прямой ID и исходная цена;
   принудительного перевода старых объявлений под управление фидом нет.
4. Перед публикацией проверяется **фактическая цена сайта**, включая
   `data/site_price_only_overrides.json`. Если цена Tilda может измениться,
   весь план блокируется **до публикации**, а не после неё.
5. Для основной позиции меняются только ячейки Avito B/D и AH, а при
   отдельном согласовании текста — X/Q. Все остальные поля XLSX
   сверяются с оригиналом. Изменённые цены сайта явно замораживаются
   в D, если раньше наследовались из B. Не меняются цены Ozon/WB/Я.Маркета,
   закупка, SKU, склад, фотографии.
6. Фид Avito Release проверяется по SHA и публикуется с резервной копией;
   повторный запуск идемпотентный, если источник уже соответствует цели.
7. **Быстрое обновление цен:** `scripts/avito_bulk_price_engine.py`
   допускает до 4 параллельных потоков, с общей скоростью не больше
   100 POST/мин, с явным approval, контрольной точкой по каждому запросу.
   Нет слепого повторного POST при неопределённом сетевом сбое. После
   всей пачки — одна полная сверка цен через API (а не 95 отдельных).
   По первому применению скорость не измерялась; выигрыш следует проверять
   на следующей реальной партии, без гарантии ускорения самой стороны Авито.
8. Два workflow:
   - `.github/workflows/avito-price-engine-tests.yml` —
     чисто офлайн-тесты, без seller secrets и публикаций.
   - `.github/workflows/avito-price-pipeline-v2.yml` —
     запускается только от изменения
     `data/avito_price_pipeline_v2_request.json`. Проверка тестов,
     inspect/apply и журнал результатов. Журнал: `data/avito_price_pipeline_v2_result.json`.

## Протокол для следующего Excel

1. Пользователь редактирует название D, текущую цену G или новую цену H.
   **C (Avito ID) не менять.** SKU, закупка, формулы и комментарии
   не используются как ключ изменения.
2. Агент сравнивает Excel с оригинальным файлом и с seller API. На каждого
   изменённого продавца создаёт строку в JSON:
   ```json
   {
     "avito_id": 8461500993,
     "kind": "main",
     "sku": "122390AK-AF",
     "expected_price": 450,
     "approved_price": 450,
     "expected_title": "Пыльник штока мехатроника DSG7 DQ200 122390AK-AF",
     "expected_site_price": 950
   }
   ```
   Это **пример без изменения цены**, а не указание запустить 450→... .
3. Для всего batch JSON: `schema_version: 2`, `mode: inspect`,
   `owner_approved: true`, `channel: avito`, обязательные флаги
   `preserve_other_channels`, `preserve_stock`, `preserve_photos`,
   `preserve_costs`, `freeze_effective_site_prices` = `true`,
   `targets: [...]`.
4. Инспекция должна завершиться
   `inspect_ok_no_seller_or_source_writes` и вывести все исключения.
   Только после успешной инспекции переключить тот же запрос
   в `mode: apply` без изменения цен и ID.
5. `apply` записывает фид и цены, выполняет ограниченную пачку,
   сверяет всё, сохраняет журнал. Если часть объявлений не подтвердилась,
   её ID остаются в отчёте. Без нового подтверждения чужие карточки
   не меняются.
6. Заголовок или описание после публикации фида может
   **появиться позже**, потому что Авито обрабатывает ссылку отдельно.
   Финальный статус названия — только по следующему успешному отчёту
   Автозагрузки и live title, не по факту загрузки файла в GitHub.

## Автозагрузка и ошибки

Авито уже настроен на автоматический почасовой забор фида; профиль
`/autoload/v2/profile` отдаёт `autoload_enabled=true`, `uploadMode=auto`.
Принудительная загрузка через Autoload API имеет отдельные ограничения
частоты (не более 1/час); **не триггерить при статусе processing**.
Запуск Autoload не смешивать с быстрой операцией seller-price API.
На проверенном отчёте были 6 заблокированных карточек и
3 ошибки параметров/описания: перед публикацией новых карточек
нужно анализировать их конкретные IDs, а не повторять полный фид вслепую.

## Что пока не утверждается

- Цена считается правильной только после решения владельца.
  Автоматическая формула стоимости отключена и не включается.
- Ускорение 95 POST проверено на искусственном API в тестах,
  но **ещё не испытано на реальной следующей партии**.
- Полное мгновенное обновление названий API не гарантируется.
- Изменения на сайте и маркетплейсах — отдельные будущие этапы.
